# 암살자 W 원본 질감·밀도 보강

W는 기존 핏빛 소용돌이의 연기·얼룩·입자 질감을 보존하면서 더 짙게 보이도록 한다. Q처럼 새 단색 도형이나 칼날 평면을 추가하지 않는다. 수련장 맵·카메라·캐릭터 선택과 Q/E/R은 보존한다.

원본 `P_Countess_BladeSiphon_RingFX`, `P_Countess_BladeSiphon_Trails`, `p_Countess_BladeSiphon_HitFX`의 프로젝트 소유 복사본을 사용한다. 원본 파일과 재질·텍스처·메시 참조는 변경하지 않는다. 복사본의 패키지 의존성을 원본과 정확히 대조한다.

## 연출 변경

- 소용돌이 입자 발생률·버스트 수 2.4배, 잔상 1.8배, 피격 1.6배.
- 기존 입자 크기 1.18배, 수명 1.20배. 원본의 곡선·랜덤 범위·UV·움직임 경로는 유지한다.
- 기존 색 곡선 비율을 유지하며 강도 1.25배, 알파 강도 1.28배. 새 단색 재질로 교체하지 않는다.
- 소용돌이·잔상의 기준 인스턴스 시간 배율은 0.85, 피격은 0.9다. 현재는 이 값에 W 시전 배속을 곱해 애니메이션·입자 전개·피격을 함께 빠르게 재생한다.
- 시전 종료·중단 때 보강한 소용돌이의 방출을 중단하고, 소유자 종료 및 기존의 한정된 FX 수명으로 정리한다.

W 정의의 피해 40, 반경 240cm, 쿨타임 6초는 유지한다. 피해 0.55초·입력 잠금 종료 0.95초는 기준 애니메이션 시간이며, 현재 기본 1.95배속에서 실제 피해 시점은 약0.282초, 조작 복귀는 약0.487초다. `Countess.Skills.WPresentation` 기본값 3은 외곽을 유지한 연결 나선, 2는 이전 외곽 선단 보강, 1은 밀도 보강본, 0은 보강 전 비교용이다. Q의 별도 표현 스위치와 독립적이다.

2026-10-16 후속 정정: 사용자의 의도는 공간 크기가 아니라 내부 안개의 촘촘함을 줄이는 것이므로 Ring 크기를1.0으로 복원했다. 새 전용 `P_CountessW_LightRing`에서 연기 발광기6개의 발생률을0.75배로 낮추고 버스트 수를 반올림해 총 예상 발생량은 기존의 약77.1%다. 입자 크기·위치·색·원본 질감·수명은 유지한다. W 기본 배속은1.5에서1.95로 높여 현재보다1.3배 빠르다. 실제 타격은 약0.282초, 복귀는 약0.487초이며 피해40·반경240cm·쿨다운6초는 유지한다.

밀도 감소만으로 각 구름 면의 짙음이 충분히 줄지 않았다는 후속 피드백을 반영해 현재는 `P_CountessW_VeilRing`을 쓴다. 내부 `WSpiralArm_0..3`의 재질만 별도 복제한 Vamp 인스턴스로 바꾸고, 실제 기존 Opacity 출력 뒤에 Saturate와0.40배를 적용한다. 외곽 `DarkPuffs_FL`·`SmokePuffs_FL` 및 물줄기·반짝임 재질은 유지한다. 기존 생성량77.1%·크기1.0·배속1.95도 유지한다. 새 base와 인스턴스만 저작하고 원본 재질 및 파티클은 저장하지 않는다.

## W 재생 속도

사용자의 느린 재생 속도 지적에 따라 `Countess.Skills.WPlayRate`를 추가했다. 현재 기본1.95, 허용 범위0.5~2다. 시전 시작에 한 번 읽어 `ActivePlayRate`로 고정하고 기존 몽타주·타격·회복·시각 큐의 배속 경로를 사용한다. Q/E/R은1배속을 유지한다. W의 소용돌이·바닥 잔상은 기준0.85×배속, 피격은0.9×배속, 무기 궤적과 칼 연기는1×배속으로 동기화한다. 파티클 에셋·밀도·재질·반경·피해·쿨타임을 바꾸지 않는다.

현재 속도 비교는 `countess_w_speed_compare.py`, `countess_w_speed_run.py`, `countess_w_speed_review.py`를 사용한다. 실제 수련장에서 같은 연결 나선 표현3을1배속/1.5배속으로 비교하고 타격·회복·시전 중단·숫자2 전환 정리·6초 쿨타임과 Q/E/R을 검증한다. 원본 프레임과 시뮬레이션 시간을 기록하고 사용자 미적 승인은 별도로 남긴다. 산출물은 `Saved/QA/CharacterPipeline/countess-w-speed-20261016`에 저장한다.

아래 기존 밀도/외곽/연결 나선 아트 비교 도구는 이전 타이밍 기준을 재현하기 위해 QA 프로세스에서만 W 배속1을 명시한다. 제품의1.5배속 기본값을 되돌리는 설정은 아니다.
## 외곽 선단 보강

2026-10-16의 `P_CountessW_RimRing`은 밀도 보강본을 별도로 복사한다. 기존 `DenseRing`, `DenseTrails`, `DenseHit`와 원본 패키지는 보존한다. 캐릭터 중앙까지 전체 밀도를 올리지 않고, `DarkPuffs_FL`·`SmokePuffs_FL` 두 연기 발광기의 시작 위치를 반경 385~415cm의 수평 원형 둘레로 바꾼다. 원본의 난류 벡터 필드·색 변화·연기 텍스처는 그대로 사용한다.

두 연기의 방출률·버스트는 밀도 보강본 대비 1.8배다. 연기 한 장의 시작 크기는 X 0.72배·Y 0.8배로 줄여, 큰 한쪽 덩어리 대신 둘레를 따라 겹치는 불규칙한 선단을 만든다. `MotionBlurSplashes`·`MotionBlurStrandsDelayed`의 메시 조각은 폭과 알파를 소폭 강화해 흩어지는 끝을 연결한다. 안쪽 불꽃·물방울·피격 효과의 설정과 판정은 유지한다. 새 프레임 Tick이나 추가 파티클 컴포넌트는 만들지 않는다.

`Tests/CountessWAutomation.cpp`의 에디터 전용 명령은 숨겨진 Cascade 발광기·모듈 연결을 기록하고 전용 복사본의 연기 위치만 작성한다. `countess_w_rim_assets.py`는 크기·발생률 등을 밀도 보강본에서 다시 계산하므로 재실행 때 배율이 누적되지 않는다. 원본 재질·텍스처·메시 패키지 의존성을 정확히 대조한다.

`countess_w_rim_run.py`는 현재 밀도 보강본과 외곽 보강본을 실제 수련장 컨트롤러 입력으로 비교한다. `countess_w_rim_review.py`는 같은 카메라·위치·시뮬레이션 시점의 원본 뷰포트 PNG와 샘플 GIF를 만든다. 해당 산출물은 `Saved/QA/CharacterPipeline/countess-w-rim-20261016`에 저장한다. 첫 선형 배치 시도인 `assets-01`·`compare-60-01`은 최종 채택본이 아니다. 최종 후보는 원형 배치인 `assets-02`다.

## 중심과 외곽의 연결

`P_CountessW_SpiralRing`은 이전 외곽 연기 2개를 보존하고, 같은 원본 연기 재질로 4개의 굵은 나선 흐름을 추가한다. 반경 약 115~124cm에서 385~400cm까지 0.24초 동안 방출 위치가 이동한다. 원본의 색 변화·노이즈·텍스처·UV 처리와 8×8 발광기 설정을 유지한다. 단색 도형이나 새 재질은 추가하지 않는다.

연기를 안쪽으로 재배치하기만 한 첫 후보는 후반 외곽이 얇아져 채택하지 않았다. 최종 작성본은 외곽 예상 생성량 70.56에 나선 예상 생성량 70.56을 더하며, 연기 생성량 상한이 이전 외곽 예산의 2배임을 명시한다. 전체 효과의 입자 예산이나 GPU 비용이 그대로라고 주장하지 않는다. 새 파티클 컴포넌트와 게임 Tick은 추가하지 않으며, 기존 소유·중단·정리 경로를 사용한다.

Cascade 복사 모듈의 `Within=ParticleSystem` 계약을 지킨다. 새 모듈의 직접 Outer는 해당 private ParticleSystem이어야 한다. GPU TypeData의 원본 캐시 포인터를 복제하지 않고 새 객체를 구성한 뒤 `UpdateAllModuleLists → BuildEmitters`로 실제 모듈에서 캐시를 재생성한다. 저장 전 외부 ParticleModule과 원본 private 패키지 참조가 남지 않았는지 검사한다. 원본 연기 셰이더에는 ParticleSubUV 노드가 없으므로, 존재하지 않는 노드를 요구하지 않고 실제 TextureSample·좌표 함수·ParticleColor 연결을 기록한다.

작성은 `countess_w_spiral_assets.py`와 에디터 전용 `CountessFXQA.WSpiral`, 검증·비교는 `countess_w_spiral_run.py`와 `countess_w_spiral_review.py`를 사용한다. 외곽이 제거된 중간 사본도 원본에서 전용 모듈로 복구하며 재실행 때 발광기나 배율이 누적되지 않는다. 통합 산출물은 `Saved/QA/CharacterPipeline/dual-character-polish-20261016`에 보관한다.

## 재현·검증

`countess_w_inventory.py`는 원본 Cascade 객체를 읽는다. Python에 전용 클래스가 없더라도 `ObjectIterator(Object)`와 실제 Unreal 프로퍼티명(`StartSize`, `ColorScaleOverLife` 등)으로 읽을 수 있다. Python 변환명만 추측해 필드가 없다고 판단하지 않는다.

`countess_w_assets.py`는 복사본 내부 분포만 수정한다. 재실행 때 원본의 값·곡선·버스트에서 다시 계산해 배율이 누적되지 않도록 한다. 복사본 외부 분포를 수정하려 하면 실패한다. 원본 재질·메시·텍스처의 직접 패키지 의존성도 동일해야 한다.

`countess_w_compare.py`는 실제 PIE 컨트롤러 입력으로 원본과 보강 W를 같은 위치·카메라·시간에 촬영한다. 세 근거리 표적의 단일 40 피해, 범위 밖 표적의 무피해, 타격 시간, Q/E/R 유지, 시전 중단, 숫자 2 전환 시 정리와 실제 6초 쿨타임을 확인한다. 반복 비교에서는 QA 프로세스에서만 쿨타임을 무시하고, 쿨타임 검사는 새 캐릭터에서 별도로 활성화한다.

`countess_w_run.py`는 별도 오프스크린 에디터를 실행한다. OS 입력을 점유하지 않고 프로젝트 설정을 저장하지 않는다. QA 프로세스에만 텍스처 캐시 512MB·가상 그림자 캐시 1024페이지를 사용한다. 고정 30·60fps 검증은 GPU 성능 벤치마크가 아니다.

`countess_w_review.py`의 비교판은 실제 뷰포트 PNG를 확대·크롭하지 않는다. GIF는 100ms 간격의 PIE 캡처 샘플이며 연속 영상 녹화가 아니다. 그림·숫자 비교는 사용자 미적 승인을 대신하지 않는다.

밀도 보강 이력은 `Saved/QA/CharacterPipeline/countess-w-density-20261015`에 보관한다. 외곽 보강 당시 모듈은 `UnrealEditor-LearnTopDown-6158.dll`, 연결 나선·궁수 정지 보강의 통합 모듈은 `UnrealEditor-LearnTopDown-6163.dll`이다. 실제 로드한 모듈과 에셋을 검사하며 이전 것을 캐시한 사용자 에디터는 저장 후 재실행해야 한다.
