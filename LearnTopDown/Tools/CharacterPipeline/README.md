# 캐릭터 제작 파이프라인

검증 범위와 비용은 프로젝트 [AGENTS.md](../../AGENTS.md)의 변경 위험도별 운영 규칙을 따른다. 아래 전체 검증 절차는 매번 작은 조정을 할 때의 기본 실행 목록이 아니다.

현재 카운테스를 정상 동작 기준으로 보존하면서 다음 캐릭터의 조작·전투 연결과 검증을 재사용한다. 사운드는 제외한다.

좌클릭 유지 평타는 공통 `KwangPlayerController`가 누름·해제와 현재 커서 조준을 관리한다. 공격 중에는 자동 입력을 예약하지 않고, 기존 `SaveAttack` 시점에 수동 예약이 없을 때만 유지 입력으로 다음 콤보를 잇는다. 마지막 타 후 기존 재시작 쿨타임을 거쳐 다음 사이클을 시작한다. 버튼 해제·새 우클릭 이동·직업 전환·포커스 상실은 유지 의도를 해제하며 기존 수동 클릭 예약은 보존한다. 스킬 중에는 평타를 겹치지 않고, 버튼을 계속 유지한 경우 종료 후 재개한다.

궁수 W의 원형 이펙트는 발사 순간 활 발사 위치에서 캐릭터 Yaw만 사용하고 Pitch/Roll은 0으로 고정한다. 실제 화살은 기존 3D 조준 방향을 유지한다. 원3개의 크기·이동·질감·반동은 유지한다. `CharacterVisualQA.CountessEPreview`의 세 E 후보는 에디터 전용 비교이며 실제 Dark Tide 정의나 피해 판정을 바꾸지 않는다.

## 구조

- `ATopDownCombatCharacter`: 이동 애니메이션 속도 전달, 등장 취소, 평타 콤보·타격·중단·복구.
- `UCharacterSkillComponent`: 슬롯별 시전, 대상 선택 방식, 재사용 대기·재입력, HUD 표시, 취소의 공통 계약.
- `UCountessSkillComponent`: 암살자의 순간이동·복귀·범위 공격·전방 파동·구속과 시각 표현.
- `ASparrowCharacter`, `USparrowSkillComponent`, `ASparrowArrow`: 스패로우의 활 발사, 비행 구간 충돌, 화살비·관통 사격·6연속 속사·누적 피해 패시브·궁극기. 공통 평타 복구와 입력을 사용한다.
- `ACharacterSkillHUD`: 공통 계약을 읽는 QWER 테스트 HUD.
- `AKwangCharacter`, `ACountessSkillHUD`: 기존 클래스 참조를 보존하는 호환 클래스. 기존 `CountessSkills` 서브오브젝트 이름도 유지한다.
- `Profiles`: 캐릭터 경로·기본 설정·평타·스킬 기본값·검증 목록. 현재 입력/HUD 범위는 최대 네 개의 QWER 슬롯이다.
- `Suites`: 카운테스 회귀검사와 스패로우의 실제 PIE 검사. 과거 성공 기록을 입력으로 사용하지 않는다.

이동과 평타 처리 본문, 카운테스의 기존 스킬 판정·모션·FX 타이밍은 유지했다. 원본과 프로젝트 에셋을 리팩터링 때문에 다시 저장하지 않는다.

과거 E 찌르기 시제품 기록(현재는 롤백됨): 암살자 E는 원본 Ultimate의 1.5~1.8초 구간을 전진·회수로 연결해 제자리에서 세 번 찌른다. 전방 280cm, 폭 110cm에서 각 15 피해를 주며 총 피해 45와 쿨다운 8초를 유지한다. 시전 취소·소유자 전환은 남은 타격과 E 효과를 정리한다. Q/W/R 정의는 유지한다. `countess_e_stabs.py`가 해당 동작·범위·중단을 기존 수련장 runner로 검사한다.

궁수 W는 기존 충전·관통 화살을 유지하고 실제 발사에만 0.24초 카메라 반동과 세 겹의 투명 굴절 파동을 붙인다. `ASparrowShotWave`는 충돌과 피해가 없는 시각 액터이며 0.42초 안에 사라진다. 소유자 전환 때 자신의 카메라 흔들림도 정리한다. 후속 보강은 파동 크기1.65배, 밝기·알파 강화와 완만한 소멸이며 전용 재질 `M_SparrowShotAirStrong`을 사용한다. 재질 저작과 발사·취소·전환 검사는 `sparrow_w_feedback.py`에서 관리한다.

궁수 후드는 `M14_CloakHood` 슬롯만 아이보리 천 재질 `MI_Sparrow_IvoryHood`로 바꾼다. 원본 Rogue 재질을 부모로 삼고 천 색상 파라미터만 덮어써 얼굴·활·망토 물리와 원본 질감을 보존한다. `Sparrow.Appearance.IvoryHood=0`은 다음 소환에서 원본 후드로 비교한다. `sparrow_ivory_hood_assets.py`가 전용 재질을 저작하며 `character_presentation_polish.py`는 두 W와 후드를 한 PIE에서 짧게 확인한다.

현재 암살자 E는 사용자 요청으로 원래 DarkTide로 복원했다. 보관된 실제 이전 소스의 Ability_E, 전방 파동45피해/900cm/발사0.36초/회복0.8초를 사용한다. 정·역재생3연찌르기 시제품은 현재 동작이 아니다. W는 기본값0인 `Countess.Skills.WPreview`를1로 켜면 몸 가까운 연기·검 그림자·짧은 외곽 잔상을 실제 수련장에서 비교할 수 있다. 기본 W는 VeilRing을 유지한다.

후속 표현 조정: 암살자 Q는 `M_CountessQOutwardThin`에서 연속 직선 몸체(Mode0, UV.y≤1.5)만 이전 길이의60%, 폭의40%로 제한한다. 길이만 줄여 뭉툭해 보이던 비율을 후속 두께 조정으로 보완했다. 점상 조각·타격 점등·이동 잔상과 기존 전체 메시 배율0.52는 유지한다. 궁수 W는 파동의 기존 크기 범위를 유지하면서 진행 방향을 반대로 적용해 활 가까이에서 큰 원으로 시작하고 전방으로 갈수록 작아진다. 궁수 망토는 실제 이동 속도를0.25초 상수로 부드럽게 반영해 이동 중 바람의 평균 세기와 좌우 변조 빈도를 높이며, 풍속·수직 성분·횡방향 상한은 유지한다. 후드 추가 변경은 사용자 레퍼런스 대기 상태이며 평타는 보존한다. 저작은 `countess_qw_refine_assets.py`, 묶음 검증은 기존 `character_presentation_polish.py`를 재사용한다.

현재 표현 보완: Q는 `M_CountessQOutwardWispy`로 길이60%·폭40%를 유지하면서 연속 몸체의 밝기를 최대40%, 알파를 최대35%로 낮추고 원본 검 FX의 `T_NoisyMask`로 면을 끊는다. 타격 점등도 밝기40%·알파50%로 낮추며 이동 잔상은 유지한다. W는 `P_CountessW_VeilRing`에서 내부 나선4개의 최종 불투명도만 `saturate(기존 출력)×0.40`으로 바꾸고 외곽2개·회전선은 유지한다. 망토의 이동 중 강제 좌우 진동은 제거한 상태로 유지하고, 이동풍은 평균110cm/s에 낮은 진폭14·8cm/s의 서로 다른 주기0.37·0.83Hz를 섞어 완만하게 바꾼다. 궁수의 Rogue 천 인스턴스만 선형 이동 전달을0.25→0.35로 풀고 회전0.1·원심력0 보호는 유지한다. 후속 급정지 관통은 Rogue cloth의 PhysicsAsset이 비어 있어 발생했다. 엔진은 mesh PhysicsAsset으로 자동 대체하지 않으므로 `AddClothCollisionSource`로 기존 `Sparrow_Physics`의 몸 충돌체를 자기 mesh의 외부 cloth 충돌원으로 제공한다. 원본 메시/천/PhysicsAsset은 저장하지 않으며 EndPlay에서 해당 source를 해제한다. 기존 두께2cm를 유지하고 CCD를 켠다. 궁수 W는 사용자 요청으로 직선 바람·발사 섬광·추가 명중 보강을 되돌리고 기존 `M_SparrowShotAirStrong` 원3개 연출을 복원했다. 원 지름만 직선 바람 보강 전의50%이며, 가까운 큰 원→먼 작은 원의 방향·밝기·질감·타이밍·카메라 반동은 유지한다. 후드와 평타는 추가 변경하지 않는다.

궁수 E는 사용자 승인으로 Rapid Shot을 사용한다. 준비0.12초 뒤0.16초 간격6발, 전체 모션1.20초, 기본 합계 피해60/쿨다운8초/사거리1800cm이다. 원본 Primary_Fire_Fast의 정방향 발사·재장전 구간을 SparrowUpperBody 슬롯에서 연결한다. 각 화살은 비관통이며 벽에 막히고 기존 Relentless 누적 피해를 적용한다. 새 우클릭·몽타주 중단·소유자 종료는 남은 발사를 취소한다. 시전 전부터 유지한 우클릭은 즉시 취소하지 않는다. R 중에도 E는 일반 화살6발이며 기존 W 연출·평타·망토는 변경하지 않는다.

## 실행

프로젝트를 빌드한 뒤 `UEClient/LearnTopDown` 폴더에서 PowerShell로 실행한다. 외부 실행기는 Python 3.11 이상이 필요하다. `-Python`, `-Engine`으로 설치 경로를 지정할 수 있다.

```powershell
# 현재 기준선·해시와 로컬 콘텐츠 복원본 저장
& .\Tools\CharacterPipeline\run.ps1 -Action Baseline

# 실제 블루프린트 기본값과 공통 계약 확인
& .\Tools\CharacterPipeline\run.ps1 -Action Inspect

# 선언한 캐릭터 기본값 적용. 값이 같으면 에셋을 저장하지 않는다.
& .\Tools\CharacterPipeline\run.ps1 -Action Install

# 스킬·콤보·등장 입력·근거리 이동을 30/60 FPS에서 검증
& .\Tools\CharacterPipeline\run.ps1 -Action Verify

# 실패한 영역만 다시 검증
& .\Tools\CharacterPipeline\run.ps1 -Action Verify -Fps 30 -Suites countess_movement
```

`-Baseline <baseline.json>`으로 기준선을 명시할 수 있다. 실행 로그와 결과는 새 `Saved/QA/CharacterPipeline/<실행 시각>` 폴더에 저장한다. 검증은 백그라운드 에디터에서 순차 실행하며 원본 에셋·설정 해시를 전후 비교한다. 이 필드의 NavMesh가 다시 생성되는 경우에는 시작점·목표점의 실제 투영과 완전 경로를 확인한 뒤 PIE를 시작한다. 빈 내비게이션 데이터를 복사해 이동 검사를 통과시키는 일을 막는다. 사운드 검사는 오디오 엔진을 켠 채 소리 컴포넌트가 생성되지 않는지 확인한다.

## 스패로우 실행

Paragon Sparrow 팩과 빌드된 네이티브 클래스가 필요하다. 원본 팩을 설치한 상태에서 기준선을 먼저 저장하고 별도 프로파일로 구성한다.

```powershell
& .\Tools\CharacterPipeline\run.ps1 -Action Baseline
& .\Tools\CharacterPipeline\run.ps1 -Action Setup -Profile .\Tools\CharacterPipeline\Profiles\sparrow.json
& .\Tools\CharacterPipeline\run.ps1 -Action Pose -Profile .\Tools\CharacterPipeline\Profiles\sparrow.json
# 요청한 자세 에셋 적용 후 새 기준선을 저장한다.
& .\Tools\CharacterPipeline\run.ps1 -Action Baseline
& .\Tools\CharacterPipeline\run.ps1 -Action Inspect -Profile .\Tools\CharacterPipeline\Profiles\sparrow.json
& .\Tools\CharacterPipeline\run.ps1 -Action Verify -Profile .\Tools\CharacterPipeline\Profiles\sparrow.json
```

에디터에서 기존 카운테스 필드 `/Game/TopDown/Lvl_TopDown`를 열고 Play를 실행한다. **숫자 1은 카운테스, 2는 스패로우**로 현재 위치에서 전환한다. 맵과 허수아비는 유지하며 이전 캐릭터의 공격·스킬·임시 FX는 정리한다. 스패로우는 Rogue 망토 스킨과 기본 Sparrow FX를 사용한다. 우클릭은 이동, 좌클릭은 활 평타다.

카메라는 카운테스의 실제 설정인 거리 2000, 각도 -50°/45°, FOV 55, 이동 지연 속도 3을 사용한다. 전환할 때 현재 캐릭터의 카메라 설정도 복사한다. `/Game/TopDown/Maps/Lvl_Sparrow`는 별도 검사와 스패로우 단독 시작에 사용할 수 있다.

| 입력 | 동작 |
| --- | --- |
| Q | Hail of Arrows: 조준한 지면에 4초 동안 8회 피해를 주는 화살비 |
| W | Piercing Shot: 0.5초 자동 충전 뒤 대상과 월드 장애물을 관통하는 화살 |
| E | Relentless: 타격 대상별 패시브 누적 상태 표시. 별도 시전 모션은 없음 |
| R | Inner Fire: 버프를 활성화한 뒤 4초 동안 좌클릭 평타마다 중앙·양쪽 화살 3발을 발사하며 대상을 관통 |

피해·쿨다운·충전 시간은 로컬 시연 값이다. W는 키를 누르면 자동 충전·발사하며, 양쪽 궁극기 화살의 피해는 중앙의 절반이다. `Sparrow.Skills.IgnoreCooldowns 0`으로 실제 쿨다운을 켤 수 있다. 사운드는 제외한다. 패시브는 이 캐릭터 팩 시기의 Relentless를 구현한다.

처음 구성할 때 Setup으로 스패로우의 프로젝트 소유 AnimBP·몽타주·캐릭터·필드를 만든다. 기본 시작 맵과 카운테스 필드는 유지한다. 이후 Install은 프로파일 기본값을 적용하며 값이 같으면 저장하지 않는다. 검증은 최초 시작·입력 1개, 이동 4개, 평타·충돌 14개, 스킬 16개, 화면 캡처 6개 케이스를 각 30/60 FPS에서 실행한다. 원래 카운테스 필드에서는 숫자 1·2 왕복·동일 캐릭터 재선택·이동 중 전환·공격과 스킬 소유자 정리를 네 개 케이스로 추가 검사한다. 정지 시 실제 카메라 위치 오차는 1cm, 각도 오차는 0.001° 이내를 확인한다. 기능 결과와 PNG 원본은 `Saved/QA/CharacterPipeline`에 보관한다. 물리 입력 조작·패키징·서버 연동·다수 FX 성능은 이 검증 범위에 포함되지 않는다.

평타는 현재 공격의 조준점을 콤보 예약과 별도로 보관하고 활의 `arrow_anchor`에서 목표까지 3차원으로 발사한다. 기존 근접 판정은 공통 기본 구현에 남아 있다. Q의 원본 Cylinder 모듈은 컴포넌트 크기로 분포 반경이 바뀌지 않으므로, 런타임 복제본의 반경만 `300 / 240`으로 조정한다. 원본 높이·낙하 운동·재질·타이밍은 유지하고 원본 파일은 저장하지 않는다. 화면 검사는 발사체의 실제 상승과 화살비의 충돌 입자도 확인한다.

W의 충전과 R의 활 불꽃은 원본 `BowEmitterSocket`에 위치·회전을 맞춰 부착한다. Q의 활 충전은 `BoneSocketActor`로 여러 활 본을 사용한다. R 강화 평타는 `R_Ability_Med_Fire` 사격 모션을 사용하고, HUD에는 3발 사격의 남은 시간을 표시한다. `sparrow_field_presentation`은 원래 카운테스 필드에서 숫자 2로 바꾼 동일 스패로우의 실제 Q/W/E/R 입력, W/R 소켓 오차 1cm, 타격·만료와 화면 13장을 각 30/60 FPS에 추가 검사한다. 저장한 화면은 별도 시각 검토가 필요하며 입자 수만으로 연출 품질을 통과시키지 않는다.

## 자세 선택과 완료 판정

각 프로필의 `presentation_contract`에 대기·이동·공격·스킬·복귀 모션의 실제 참조와 선택 이유를 기록한다. 에셋 연결과 기능 통과는 원작의 상태 전환 재현 여부를 증명하지 않는다. 원작 행동을 검증했다고 기록하려면 원작 비교 자료의 파일과 SHA-256을 별도로 선언해야 한다. 현재 카운테스는 승인된 프로젝트 기준선, 스패로우는 사용자가 요청한 자세 변형이며 두 프로필의 원작 행동 검증 상태는 `unverified`다.

스패로우의 평상시 대기는 `idle_relaxed`의 183~336 프레임을 프로젝트 소유 사본으로 분리했다. 파일 전체의 시작과 끝은 활을 겨누므로 사용하지 않는다. 원본 RAW 본 포즈를 측정해 손이 머리보다 30cm 이상 낮은 구간과 반복 경계를 선정했다. 이동은 원본 Sprint의 지형·회전 샘플을 복제한 BlendSpace를 사용한다. `ShouldUseCombatLocomotion`은 공격·시전·R 버프 상태를 게임 스레드 AnimBP 업데이트에서 읽는다. AnimGraph는 저장된 bool만 사용하고 0.2초 동안 전환한다. E 입력은 자세를 바꾸지 않는다. `sparrow_pose`는 원래 필드에서 반복 대기, 이동, 평타·Q/W 복귀와 R 버프 종료를 30/60 FPS로 검사한다.

`Pose`는 프로필에 선언한 원본 SHA-256과 프레임을 입력으로 사용하며 과거 QA 성공 기록에 의존하지 않는다. 원본이 바뀌면 포즈를 다시 측정할 때까지 중단한다. 저장 범위는 선언한 스패로우 자세 사본 8개이며 원본 팩·카운테스·필드는 보호한다.

파이프라인 결과의 `passed`와 `functional_passed`는 기능 결과다. `completion_status`는 별도 시각 검토가 없으면 `pending_visual_review`다. 검토자는 실제 PNG를 확인하고 프로필·이미지·에셋 SHA-256, 검토자, 상태별 화면을 기록한 JSON을 `-VisualReview <review.json>`으로 전달한다. 화면 누락이나 해시 변경은 승인을 무효화한다. 전체 프로필을 통과하고 유효한 시각 검토가 있어야 `complete`가 된다. 일부 suite만 재검사한 결과는 `scoped_verification_complete`로 구분한다. 검토 형식과 변조 검사는 `presentation_contract.py`, `test_presentation_contract.py`를 따른다.

검토를 마친 뒤에는 `-Action Review -Profile <profile.json> -Baseline <검증에 사용한 baseline.json> -ResultDirectory <기존 실행 폴더> -VisualReview <review.json>`으로 결과를 확정한다. 프로필 전체의 30/60 FPS 결과, 각 기능 보고서 해시, 보호 기준선과 시각 검토 지문을 다시 확인하므로 기능 검사를 반복 실행할 필요가 없다.

`SM_Sparrow_Arrow`의 원본 좌표는 화살촉 -Z, 깃 +Z다. 별도 투사체 모델에는 상대 Pitch +90°를 적용해 화살촉을 실제 비행 +X축에 맞춘다. 검사는 모든 샘플의 모델 전방·비행 방향 내적이 0.999 이상인지 확인한다. 원본 OBJ·경계상자 조사 결과는 `Saved/QA/Sparrow/arrow-geometry-20261014`에 보관한다.

## 로컬 복원

기준선 폴더에는 `baseline.json`, 원본 코드·설정 백업, `character-project-content.zip`이 있다. 초기 카운테스 기준선의 ZIP 이름은 `countess-project-content.zip`이며 복원기는 두 이름 모두 기록에서 읽는다. ZIP은 프로젝트의 `Content/TopDown`, 해당 맵의 `Content/__ExternalActors__/TopDown`·`Content/__ExternalObjects__/TopDown`, `Config`를 보관한다. 외부 액터 저장 방식의 맵은 이 파일들이 함께 있어야 복원된다. 원본 콘텐츠는 해시만 기록하고 ZIP에 포함하지 않는다. 이 로컬 복원본과 기록은 `Saved` 아래에 두며 공개 저장소에 넣지 않는다.

새 환경에는 UE 버전과 필요한 원본 콘텐츠를 먼저 준비하고, Source·Tools·uproject를 가져온다. 이 프로젝트의 콘텐츠에는 Paragon Countess/Kwang 및 엔진 템플릿 콘텐츠 참조가 있으므로 카운테스 팩 하나만으로 전체 프로젝트가 복구되는 것은 아니다. 같은 엔진 버전과 원본 패키지를 준비한 뒤 아래 명령으로 프로젝트 콘텐츠를 복원한다.

```powershell
& .\Tools\CharacterPipeline\run.ps1 -Action Restore `
  -Baseline <기준선폴더\baseline.json> -Destination <복원할프로젝트폴더>
```

복원기는 ZIP 해시, 모든 경로와 기존 파일 충돌을 먼저 확인한다. 이미 같은 파일이면 건너뛰고, 다른 파일이면 덮어쓰지 않고 중단한다. 반복 실행 결과가 같도록 구성했다. 기준선은 변경 승인 후 새로 저장하며, 실패한 결과를 덮어서 정상 기준으로 취급하지 않는다.

## 다음 캐릭터의 작업 순서

1. **조사·범위 확정**: 출처와 필요한 원본 패키지, 모델·스켈레톤·이동 모션·콤보·스킬·FX를 목록화한다. 누락 자료와 대체 범위를 먼저 기록한다.
2. **캐릭터 구성**: 프로파일 템플릿을 복사해 실제 경로를 채운다. 골격에 맞는 AnimBP, 몽타주 슬롯, 모델 오프셋·크기, 카메라와 이동 그래프를 준비한다. 기존 카운테스용 슬롯·소켓·그래프를 다른 골격에 무조건 적용하지 않는다.
3. **고유 스킬 연결**: 공통 스킬 컴포넌트를 상속해 슬롯 시전·표시·대상 방식·취소를 구현한다. 고유 스킬의 판정과 연출은 그 컴포넌트가 소유한다. 입력·평타·HUD를 캐릭터마다 복사하지 않는다.
4. **시각 표현**: 기능과 판정을 먼저 고정하고 원본의 핵심 느낌·타이밍과 쿼터뷰 가독성을 맞춘다. 러프/정밀 수준은 캐릭터별 선택이며 동작·판정의 완료 기준과 분리한다.
5. **묶음 검증**: 시작·이동·회전·정지, 작은 목표의 반복/유지 입력, 공격 연타·중단·피격, 대상 소멸·벽·사거리, 임시 FX 정리 등을 검증한다. 새 스킬에는 그 행동에 맞는 검사를 추가한다. 카운테스 전용 검사를 이름만 바꿔 다른 캐릭터 검사로 사용하지 않는다.
6. **기준선 저장**: 설치 설정·검증 결과·동일 조건 시연 화면을 보관하고 기존 캐릭터 회귀검사를 통과시킨다.

새 네이티브 캐릭터는 공통 기반에 고유 컴포넌트를 연결한다. 기존 카운테스 호환 클래스가 같은 패턴의 실제 예다.

```cpp
AHeroCharacter::AHeroCharacter(const FObjectInitializer& ObjectInitializer)
    : Super(ObjectInitializer.SetDefaultSubobjectClass<UHeroSkillComponent>(SkillComponentName))
{
}
```

프로파일 설치기는 기본값 연결을 자동화한다. 임의의 캐릭터 골격 리타게팅이나 AnimBP 그래프 설계를 자동으로 해결하는 도구는 아니다. 골격·이동 그래프·카메라 구성은 캐릭터 구성 단계에서 확인해야 한다.

## 천·효과의 시간 구간 검증

사용자 명칭은 궁수(Sparrow), 암살자(Countess)다. 두 프로필의 `character_visual_quality`는 원래 필드에서 30/60 FPS로 실행한다. 이동 시작·급회전·반전·정지, 평타 및 Q/W/E/R의 준비·발동·복귀·잔여 효과를 실제 컨트롤러 입력으로 검사한다. 궁수 E는 능동 6연속 속사이며 Relentless 누적 피해는 별도 상시 패시브로 유지한다.

천 입자를 매 시뮬레이션 프레임 월드 좌표로 측정한다. 궁수의 상한은 머리 위 최대 30cm/95백분위 10cm/수평 반경 130cm, 암살자는 머리카락을 고려해 최대 35cm/95백분위 26cm/수평 반경 90cm다. 1.5배 R 변형에서 화면상 정상인 머리카락의 95백분위 높이 25.21cm가 관측되어 해당 기준만 25cm에서 26cm로 보정했다. 기존 초과 원본과 화면 검토 근거는 `countess-feast-speed-20261015/quality-calibration.json`에 남긴다. 암살자는 천이 있는 LOD에서 1~3개를 검사하며, 천 렌더 데이터가 없는 LOD의 계산 생략은 허용한다. 실제 LOD·천 렌더 데이터 유무·강제 중단 여부를 함께 기록한다. 천이 있는 LOD의 입자 소실·비정상 좌표·시뮬레이션 정지는 실패다. 상한 통과와 별도로 화면의 관통·과도한 펄럭임을 검토한다.

활성 입자의 실제 재질을 메시 재질 덮어쓰기 여부까지 반영해 검사한다. 사용되지 않는 RequiredModule 재질 이름만으로 결함을 단정하지 않는다. 궁수 Q의 별도 카메라 굴절 판 `DrawABead/FX/P_ReleaseArrow`는 금지한다. 금색 발사체와 낙하 효과는 유지한다.

Review는 양 FPS의 원본 시간 기록·SHA-256·프로필·실행 소스 지문과 시각 관찰(천 안정성, 불필요한 판 노출, 스킬 전 구간, 복귀)을 요구한다. 중간 프레임 누락·짧은 관찰 구간·확인되지 않은 스킬은 완료 승인할 수 없다. 원작 동작 재현 여부는 별도 항목이다.

검사 구현은 렌더러의 `ComponentRelativeTransform → ComponentToWorld` 좌표 경로와 `FParticleMeshEmitterInstance::GetMeshMaterials`를 사용한다. `ERM_LightsOnly`는 표면 재질 검사에서 제외하며 빛의 존재는 입자 기록에 남긴다. 시전 종료 이후에도 활성 입자가 남으면 실제 소멸까지 기다리고, 12초 안에 정리되지 않으면 실패한다. 확대 캡처는 `CharacterVisualQA.Camera` 런타임 명령을 사용한다. PIE에서 `set_editor_property`로 SCS 컴포넌트가 재생성되어 검사 대상이 바뀌는 것을 방지하고, 원래 카메라 거리·FOV와 같은 메시 인스턴스가 복원되는지 검사한다.

궁수 망토는 `ConfigureTopDownCloth`가 BeginPlay에서 캐릭터 인스턴스의 선형 관성 0.25, 회전 관성 0.1, 원심력 배율 0, 감쇠 0.15/국소 감쇠 0.25를 설정한다. 천 시뮬레이션과 원본 천 에셋은 유지한다. 두 캐릭터는 45도 이상 한 프레임 회전 시 엔진의 천 순간이동 처리를 사용한다. 암살자의 천 물성은 변경하지 않는다.

능동 스킬은 시전 플래그뿐 아니라 표적의 실제 피해까지 요구한다. 지형에 막힌 R 등 실패 시전 화면은 정상 연출 증거로 승인하지 않는다. 궁수 E는 패시브이므로 해당 입력에서 별도 시전·피해가 생기지 않는 것을 검사한다.

화면 저장은 전역 HighResShot 대신 `CharacterVisualQA.Capture`가 지정된 PIE 뷰포트를 직접 읽어 PNG로 동기 저장한다. 실제 뷰포트 크기를 기록하며 OS 창·커서는 조작하지 않는다. 캡처 직후와 검사 종료 시 파일 SHA-256을 비교하고, Review에서도 다시 비교한다. 뒤늦은 덮어쓰기나 이미지 변경은 완료를 차단한다.

오프스크린 에디터 실행은 프로젝트별 OS 파일 잠금으로 한 번에 하나만 허용한다. 중복 파이프라인/진단 작업도 같은 잠금을 공유하며 다른 검사 종료를 기다린다. GPU 메모리 경쟁 때문에 텍스처·화면 품질이 떨어진 병렬 실행을 최종 시각 증거로 사용하지 않는다.

평상시 자세를 선택할 때는 손 높이·루프 경계와 함께 이동/대기의 골반·머리·발 중심을 측정한다. 정지 한 프레임의 튐이 줄어도 같은 큰 변위를 천천히 보여 주는 것일 수 있으므로, 정지 전후 전체 이동량과 실제 화면을 함께 본다. 궁수의 원본 후보 비교·전용 대기 사본·짧은 도착 회전 보정과 중단 검증은 `SparrowStopPolish.md`에 기록한다. 여러 직업의 구현 담당과 에디터·빌드 통합 담당을 나누는 규칙은 `ParallelCharacterWork.md`를 따른다.

## 암살자 궁극기의 접근과 공격 모션

Feast(R)는 원본 1.05초부터 1.5배속으로 도약·찍기 모션을 재생한다. 준비0.2초 뒤0.2초 동안 지상 캡슐을 sweep하여 접근하며, 공중 높이는 원본 포즈가 표현한다. 약0.4초에 도착,0.5초에 피해80,0.8초에 복귀한다. 접근 도중 벽·중단은 이동과 타격을 취소하고, 타격 시 추가 순간이동하지 않는다. 궁수 Q는 원본 복제본 화살 emitter 발생량만1.8배로 하고 실제반경300cm 황금 원을4초 유지한다. 피해·펄스·지속은 유지한다.

도착과 타격 때 모두 대상·사거리·시야·착지 위치를 검증한다. 실제 바닥에 높이를 맞추고 이미 도착한 위치에서는 무이동 반환값으로 거절하지 않는다. 피해량·사거리·쿨다운, Q/W/E·궁수와 원본 에셋은 유지한다. 근거리·480cm·이동 대상에서 빠른 도착, 대상 옆에서 피해 없이 재생되는 공격 준비 구간, 타격 1회, 복귀, 도착 후 대상 소멸과 중단 복구를 검사한다.
